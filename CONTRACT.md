# Internal implementation contract

This is the internal implementation contract for a standalone external-action reliability library. It contains no product-specific dependencies.

The public factory is `createActionLedger({store})`. References use `{namespace, key}`. Public methods are `enqueue(input)`, `get(ref)`, `claim(ref, {workerId, leaseMs})`, `dispatch(claim, adapter)`, and `resolve(ref, {expectedRevision, actor, evidence, receipt})`. `resolve` only confirms success in v0; it never reopens an uncertain action.

States: `ready`, `claimed`, `executing`, `succeeded`, `failed`, `uncertain`. Claims which expire before dispatch may be reclaimed. Executing actions whose leases expire become uncertain, never ready. Reads are observational; `claim` and `resolve` normalize expired executions. `dispatch` normalizes expiry before beginning or settling. A unique token and attempt identity fence stale writes. Dispatch intent is persisted before invoking an adapter, without holding any storage transaction over the provider call. Rejected dispatch-intent persistence must prevent that call even if its commit may have succeeded.

Adapters return `{outcome:'applied',receipt: JSON}` or `{outcome:'not_applied',reason: string,retryable: boolean,retryAfterMs?: number}`. `not_applied` asserts zero current AND future effect, including partial effects, delayed requests, or queued provider jobs. Exceptions and invalid results are uncertain. Retry count counts dispatch intents, not claims. No automatic retries of uncertain actions; no exactly-once guarantee. Adapters must perform one logical operation and disable hidden retries.

Record is JSON: identity/ref, immutable kind/payload/maxAttempts, revision, state, createdAt/updatedAt/availableAt milliseconds, current claim or null, attempts array, resolution or null. Keeping attempts in the same record makes updates atomic. Enforce a conservative maxAttempts limit (100), payload JSON support and copy isolation. Reject stale writes to protect resolved outcomes; rejected late receipts are not persisted automatically.

Storage contract: `store.read(ref) -> record|null`; `store.transact(ref, synchronousMutator) -> arbitrary JSON-compatible result`. Mutator receives `(record|null, authoritativeNowMs)` and returns `{record, result}`. It must run exactly once inside a transaction/lock, with isolated snapshots. It must not perform I/O. A null resulting record means leave a nonexistent row absent, or delete a transaction-only placeholder. An error rolls back; a transaction may still have committed if the connection fails around commit. `result` may be null. All committed nonnull records are objects. Namespace and key validated by core. Stores must not expose mutable references. Initial uniqueness is `(namespace, key)`.

PostgreSQL factory `createPostgresStore(pool, {schema='public'}={})` accepts a pg-compatible pool `connect()` returning a client with `query()` and `release()`. Returns the above contract plus `initialize()` (explicit DDL; don't run per action). Table is `external_action_ledger_v1` in a strictly validated quoted schema. It contains namespace text, key text, record jsonb nullable for an uncommitted placeholder, primary key(namespace,key). In transact: BEGIN, INSERT null placeholder ON CONFLICT DO NOTHING, SELECT record FOR UPDATE, then SELECT clock_timestamp() for authoritative time AFTER acquiring the lock. Run mutator synchronously, UPDATE or DELETE placeholder, COMMIT. Roll back on failure; release in finally. No SQL interpolation except a validated schema identifier. read does not create rows. initialize creates table in an already-existing schema, never drops or creates schemas. Caller owns pool lifecycle.

Native integration tests use an explicitly supplied disposable `ACTION_LEDGER_TEST_DATABASE_URL`, isolated generated schema, multiple pg connections, cleanup only that schema. Test fails clearly if env is missing. PGlite SQL smoke uses a compatible wrapper, clearly isn't native concurrency validation. A GitHub Actions PostgreSQL service will run native tests on a normal host. No cloud credentials or production configuration.
